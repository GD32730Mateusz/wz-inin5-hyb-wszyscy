# Zasady współpracy – Przewodnik po stolicach Europy

## Branch naming
- Format: miasto-imie, np. reykjavik-mateusz
- Używaj małych liter i myślników

## Tworzenie Issue
- Każda większa zmiana lub błąd musi mieć issue
- Używaj tagów: `feature`, `bug`, `documentation`
- Opisuj krok po kroku, czego dotyczy problem

## Pull Request
- Jeden pull request = jedna funkcjonalność
- W opisie PR: co dodano, link do Trello, screeny jeśli to zmiana wizualna
- PR powinien być przypisany do osoby i oznaczony etykietami
